1. Long-window (288 = 24 h) features carry 46% of total mean |SHAP|, short-window and lag/diff features 26%; the top feature is roll_std_288. Slow, 24-hour-scale context dominates, so this machine's failures look like gradual drift away from its normal level rather than sudden spikes.
2. hour and dayofweek together contribute 25.3% of total mean |SHAP|. That is material: the model is partly keying on the clock, which is risky because it would misfire when the operating schedule changes or in a new time zone, and it can memorise when past incidents happened.
3. An additivity error near zero means base value plus the per-feature contributions reproduces the model output exactly, so every alert can be justified as a precise, auditable sum of feature effects with nothing unexplained left over.
4. Log classifier: PR-AUC is 0.996 with Level/Component metadata and 0.995 from message content alone (gap +0.001). I would deploy the content-only model: metadata such as Level is set by the same component that raises the alert, so it restates the label and would not generalise; the content tokens already carry the signal.
