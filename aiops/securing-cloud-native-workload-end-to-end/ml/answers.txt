1. No single event in an attack window has a unique rule name, but the windows combine many distinct rules and processes (n_rules, n_procs) plus shell and secret-read counts in one 5-minute window. Each signal is weak alone; together they are far outside the baseline, so the Isolation Forest isolates them in very few splits.
2. A triage ranker orders work for analysts; it is not a blocker, so missing an attack (recall) matters more than reviewing a few extra windows (precision). To cut false positives: lower contamination, add features such as business-hours flags or per-pod baselines, and allowlist the known benign deploy-hook pattern.
3. Without the night flag, the live windows are driven by n_shell (interactive shells), n_secret (reads of /vault/secrets by a non-application process) and n_rules (several distinct rules in one window), all rare in the baseline week.
4. Evasion: the attacker moves slowly, spreading actions over many windows or using the allowed interpreter (python) so counts stay low. Compensating controls: the Falco allowlist rule on /vault/secrets (Task 7), default-deny NetworkPolicy that blocks exfiltration (Tasks 5-6), read-only root filesystem and non-root enforcement from Gatekeeper (Task 4), and Vault policy limiting what a stolen token can read (Task 6).
